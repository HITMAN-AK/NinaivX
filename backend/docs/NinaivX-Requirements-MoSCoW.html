NinaivX — Requirements Specification (MoSCoW)

Derived from the Literature Gap Analysis · Ashwin Kumar Ramesh Kumar · MSc AI, University of Sheffield

Requirements are specified using MoSCoW prioritisation (Must, Should, Could, Won't have this time) and are derived from the gaps identified in the Literature Survey (see the Gap Analysis). Each requirement records the gap it addresses and its delivery status, so the document shows why each requirement exists, what is delivered, and what is deliberately omitted. Requirements marked Enabling are engineering necessities that make the gap-driven requirements deliverable; those marked Scope come from the product vision rather than a literature gap.

Status key: ✓ Implemented · ◑ Partial · ⧖ Planned · ✗ Omitted · — Out of scope

MUST HAVE — core requirements without which the system has no value

IDRequirementGapStatusWhere satisfied / notes
M1Authenticate every request with a verified Supabase token (JWT).G6✓app/core/auth.py; protects the deceased's sensitive data. Rejects invalid tokens (401).
M2Onboard a user and store their profile (name, age, language).Enabling✓POST /api/onboard, GET /api/me.
M3Create personas of two types: deceased (legacy) and companion.G9✓POST /api/personas; PersonaType enum. Extends scope beyond the deceased-only products.
M4Route a conversation to the correct persona type automatically.G9, G3✓Supervisor router; enables different safety profiles per mode.
M5Hold a coherent, generative conversation in character as the persona.G1✓POST /api/chat → LangGraph agent → Claude. Answers novel questions, unlike static memorials.
M6Remember previous conversations across sessions.G1✓Rolling summary checkpoint in Conversation table.
M7Convert the AI reply to natural speech (text-to-speech).G2✓voice_service.text_to_speech (ElevenLabs).
M8Convert the user's speech to text (speech-to-text).G2✓voice_service.speech_to_text (ElevenLabs Scribe).
M9Support an end-to-end voice conversation (audio in → audio out).G1, G2✓POST /api/voice-chat (full loop, verified live).
M10Air-gap the deceased persona from the internet to prevent fabricated information.G3, G6✓Deceased node has no tools bound — a code-level guarantee, not a prompt request.
M11Enforce per-user data isolation; a user may only access their own personas.G6✓Ownership check on every persona route.
M12Persist users, personas and memory in a database.Enabling✓Supabase (PostgreSQL) via SQLAlchemy.
M13Ground the deceased persona only in its stored personality and memory (no invented sources).G3◑Grounded via prompt-context injection of personality + summary. A full vector-retrieval (RAG) pipeline over uploaded documents is not implemented — see C1.
M14The architecture shall be openly documented and reproducible.G7✓README, architecture diagram and full source; contrasts with closed commercial products.
M15The safety design shall be empirically evaluated (project-level requirement).G8⧖Planned: a technical evaluation measuring fabrication in the air-gapped legacy mode vs the web-connected companion mode, using synthetic personas. No human participants, so no ethical approval is required (no user study is conducted).

SHOULD HAVE — important, included but not strictly vital

IDRequirementGapStatusWhere satisfied / notes
S1The companion persona may use the live internet for current information.G9✓web_search tool bound to companion node (ReAct loop).
S2Clone a voice from an uploaded audio sample.G2✓POST /api/clone-voice (ElevenLabs).
S3Assign a cloned or ready-made voice to a persona.G2✓clone-voice (persona_id), select-voice, PATCH persona.
S4Manage personas: list, view, update, delete.Enabling✓GET/PATCH/DELETE /api/personas[/{id}].
S5Keep perceived latency low so conversation feels natural.G1✓Memory summary runs as a FastAPI background task.
S6Degrade gracefully if a voice provider key is absent (no crash).Enabling✓Lazy voice service; returns 503 instead of failing at startup.
S7Respond in the chosen language (per persona), colloquially.Scope✓Each persona has its own language; the prompt drives natural, colloquial, slang-aware replies and TTS speaks them. Native accent depends on the voice asset (upload/clone a native voice — the default library is English).
S8Produce speech-appropriate text (no emojis or stage directions).G2✓TTS-tuned system prompts (agents/prompts.py).
S9Disclose to the user that they are speaking with an AI (transparency).G4✓Persona stays in character but honestly confirms it is an AI if directly asked (verified live); public notice via GET /api/disclosure and in profile/persona responses.
S10Support healthy grieving and closure; avoid engagement-maximising or dependency-forming design.G5◑By design: prompts orient toward comfort and closure; no gamification, streaks or engagement mechanics. Effectiveness to be assessed in the evaluation (M15).
